ეს დოკუმენტი წარმოადგენს `@analytics_todo2.md`-ისა და ხელნაწერი სპეციფიკაციის (`image-3.png`) სრულფასოვან არქიტექტურულ, მონაცემთა ბაზის და UI/UX იმპლემენტაციის გეგმას.

## 1. ხელნაწერი ფილტრებისა და მოთხოვნების ზუსტი დეკოდირება

ხელნაწერი ფურცლისა (`image-3.png`) და ტექსტური დავალების (`analytics_todo2.md`) შეჯერებით, სისტემაში ინტეგრირდება ყველა ფილტრი 2 სვეტისა და დროითი/ლოგიკური ოპერატორების მიხედვით:

### მარცხენა სვეტი (სუბიექტი, ვალდებულება, გრაფიკი, იურიდიული და საოპერაციო ფილტრები)
1. **ძიება სახელით** — ფიზიკური პირის სახელი ან იურიდიული პირის დასახელება (`firstName`, `companyName`).
2. **გვარით / ქვითრით** — ფიზიკური პირის გვარი (`lastName`) და ასევე ქვითრის/საქმის ნომერი (`receiptNumber`, `caseNumber`).
3. **პ/ნომრით (ან ს/კ-ით)** — 11-ნიშნა პირადი ნომერი ან 9-ნიშნა საიდენტიფიკაციო კოდი (`personalId`, `taxId`).
4. **მისამართით** — იურიდიული და ფაქტობრივი მისამართი, ქალაქი, უბანი (`legalAddress`, `actualAddress`, `district`).
5. **მაილით (ელ-ფოსტით)** — დებიტორის/კომპანიის/დირექტორის ელ-ფოსტა (`email`, `directorEmail`).
6. **T ნომრით (ტელეფონით)** — დებიტორის, დირექტორის ან საკონტაქტო პირის ტელეფონის ნომერი (`phone`, `directorPhone`).
7. **ვალის წარმოქმნის თარიღი** — თარიღების დიაპაზონი (`debtOriginationDate`: საწყისი თარიღიდან – საბოლოო თარიღამდე).
8. **ვადაგადაცილება 3 წელზე მეტი (ხანდაზმულობის კონტროლი)** — საქმეები, სადაც ვალის წარმოქმნიდან გასულია >3 წელი (1095 დღე) ან სრულდება 3-წლიანი ვადა (ხანდაზმულობის რისკის მონიტორინგი).
9. **გრაფიკი სტანდარტული** — `ScheduleType.STANDARD` (1-დან 12 თვემდე გრაფიკები) + გრაფიკის სტატუსი (აქტიური, დარღვეული, დასრულებული).
10. **გრაფიკი არასტანდარტული / მიმდინარე** — `ScheduleType.NON_STANDARD` (12 თვეზე მეტი / გახანგრძლივებული გრაფიკები).
11. **იურისტი** — კონკრეტული იურისტის არჩევა (`assignedLawyerId`) ან ყველა იურისტის შედარება.
12. **სასამართლოში** — სასამართლო წარმოებაში არსებული საქმეები (`LegalCaseStatus.IN_COURT`, სასამართლო ინსტანცია, დაწერილი სარჩელები).
13. **აღსრულებაში** — აღსრულების ეროვნულ ბიუროში გადაცემული საქმეები (`DECISION_ENFORCED`, `ENFORCEMENT`).
14. **ყადაღა** — საქმეები/კომპანიები, რომლებზეც დადებულია ყადაღა/ინკასო (`hasSequestration = true`).
15. **ვიზიტორი** — საველე ოფიცერი (`FieldVisitTask.officerId`), ვიზიტის სტატუსი და პერიოდი.
16. **კრედიტ მენეჯერი (გარე/შიდა მენეჯერი / ოპერატორი)** — ქოლ-ცენტრის ოპერატორი (`CrmCallLog.operatorId`, მაგ: თეონა პეტრიაშვილი).
17. **ჯგუფის უფროსი (Team Lead)** — ოპერატორების/ვიზიტორების ჯგუფის ხელმძღვანელი (`teamLeadId`).
18. **გამოსული ზარების რაოდენობა (გაზომვა ზარების მიხ.)** — ზარების რაოდენობის დიაპაზონი (მინ–მაქს) და დღის საათობრივი ინტერვალი (მაგ: `08:00` – `18:00`).
19. **პერიოდის მიხედვით (1–30 დღე / 1–60 დღე / 60–90+ დღე / Custom)** — ვადაგადაცილების დღეებისა და აქტივობის პერიოდის ჭრილი.

### მარჯვენა სვეტი (მაკრო, კორპორატიული და წყაროს ფილტრები)
1. **წლის მიხედვით** — წლების ფილტრი (`2023`, `2024`, `2025`, `2026`) + **წინა წელთან შედარების (YoY) გადამრთველი**.
2. **კრედიტორის და პროდუქტის მიხედვით** — კონკრეტული კრედიტორი კომპანია (`creditorId` / `creditorName`) და ვალდებულების/პროდუქტის ტიპი (`B2B დისტრიბუცია`, `სესხი`, `ლიზინგი`, `მომსახურება`).
3. **დირექტორის მიხედვით** — კომპანიის დირექტორის სახელი, გვარი ან პირადი ნომერი (`directorName`, `directorLastName`, `directorPin`).
4. **დამფუძნებლის მიხედვით** — კომპანიის დამფუძნებლის (ბენეფიციარი მესაკუთრის) სახელი, გვარი ან პირადი ნომერი (`founderName`, `founderPin`).
5. **ფაილის და ფილიალის მიხედვით** — იმპორტირებული Excel რეესტრის ფაილის სახელი (`sourceFile`, მაგ: `debtors_october.xlsx`) და რეგიონული ფილიალი (`branch`: თბილისი, ბათუმი, ქუთაისი და ა.შ.).

   - **Tab 2: იურიდიული სამსახურის KPI & სასამართლო ფაიფლაინი** (ბოლო 6 თვის ან არჩეული პერიოდის სარჩელები, ყადაღები, სასამართლოში/აღსრულებაში მყოფი და მოგებული საქმეები იურისტების მიხედვით).

## 3. მონაცემთა ბაზის სქემის გაფართოება (`backend/prisma/schema.prisma`)

ყველა ფილტრისა და დროითი შედარების ზუსტი მუშაობისთვის `schema.prisma`-ში დაემატება შემდეგი ველები და ინდექსები:

### 3.1. `DebtClaim` (სესხის/დავალიანების საქმე)
- `debtOriginationDate DateTime?` — ვალის წარმოქმნის ზუსტი თარიღი (3-წლიანი ხანდაზმულობის გამოსათვლელად: `debtOriginationDate + 3 წელი`).
- `statuteExpiredAt DateTime?` — ხანდაზმულობის დადგომის თარიღი (ავტომატურად ან ქვერით გამოთვლებადი).
- `productType String? @default("B2B_SUPPLY")` — პროდუქტის ტიპი (`B2B_SUPPLY`, `LOAN`, `LEASING`, `SERVICE`).
- `branch String? @default("თბილისი - ცენტრალური")` — ფილიალი.
- `sourceFile String?` — ატვირთული ფაილის იდენტიფიკატორი (ფაილის მიხედვით ფილტრაციისთვის).
- `assignedOperatorId String?` — პასუხისმგებელი კრედიტ მენეჯერი (ოპერატორი).
- `teamLeadId String?` — ჯგუფის უფროსი.

### 3.2. `CompanyProfile` და `StagedRegistryItem` (დირექტორი და დამფუძნებელი)
- ემატება დამფუძნებლის ველები:
  - `founderFirstName String?`
  - `founderLastName String?`
  - `founderPin String?`
- `StagedRegistryItem`-ში ემატება `branch String?` და `productType String?`.

### 3.3. `LegalCase` (იურისტის მიღწევების დეტალური აღრიცხვა)
- `outcome String?` — საქმის შედეგი: `IN_PROGRESS` (მიმდინარე), `WON` (მოგებული), `SETTLED` (მორიგებით დასრულებული), `LOST` (წაგებული).
- `lawsuitFiledAt DateTime?` — სარჩელის შეტანის თარიღი.
- `sequestrationAppliedAt DateTime?` — ყადაღის დადების თარიღი.
- `enforcedAt DateTime?` — აღსრულებაში გადაცემის თარიღი.
- `resolvedAt DateTime?` — მოგების/დასრულების თარიღი.
- `recoveredAmount Decimal? @db.Decimal(12, 2)` — იურისტის მიერ ამოღებული/მოგებული თანხა.

### 3.4. `CrmCallLog` (ოპერატორის ზარების საათობრივი და რაოდენობრივი აღრიცხვა)
- `durationSeconds Int @default(45)` — ზარის ხანგრძლივობა წამებში.
- `callHour Int @default(12)` — ზარის განხორციელების საათი (`0`–`23`, რათა `08:00`–`18:00` ფილტრაცია მყისიერად შესრულდეს ინდექსით).
- `teamLeadId String?` — ჯგუფის უფროსის ID.

## 4. Backend API არქიტექტურა (`backend/src/modules/analyst`)

`AnalystController`-სა და `AnalystService`-ში დაემატება მძლავრი ანალიტიკური ენდპოინტები:

1. **`POST /api/v1/analyst/bi/query`**
   - იღებს სრულ ფილტრის ობიექტს (`AnalystBiFilterDto`: მარცხენა სვეტის 19 პარამეტრი + მარჯვენა სვეტის 5 პარამეტრი + `dateFrom`, `dateTo`, `compareWithPreviousYear`, `hourFrom`, `hourTo`).
   - აბრუნებს:
     - გაფილტრულ საქმეების სიას პაგინაციით და სრული დეტალებით.
     - ჯამურ KPI მეტრიკებს (სულ საქმეები, ჯამური თანხა, ამოღებული თანხა, საშუალო გადაცილება).

2. **`GET /api/v1/analyst/bi/schedules-comparison`**
   - პარამეტრები: `dateFrom`, `dateTo`, `scheduleType` (`STANDARD` | `NON_STANDARD` | `ALL`), `compareYoY=true`.
   - ითვლის:
     - არჩეულ პერიოდში (მაგ: 1 სექტემბერი – 1 ოქტომბერი) შექმნილი სტანდარტული და არასტანდარტული გრაფიკების რაოდენობასა და მოცულობას (₾).
     - წინა წლის ზუსტად იგივე პერიოდის მაჩვენებლებს და პროცენტულ ზრდას (`YoY Growth %`).
     - 12 თვის ჭრილში (თვეების მიხედვით) ზრდის დინამიკას გრაფიკის ასაგებად.

3. **`GET /api/v1/analyst/bi/legal-performance`**
   - პარამეტრები: `dateFrom`, `dateTo` (მაგ: ბოლო 6 თვე ან 1 იანვარი – 1 ივნისი), `lawyerId` (არასავალდებულო).
   - ითვლის თითოეული იურისტისთვის და ჯამურად:
     - დაწერილი სარჩელების რაოდენობა (`lawsuitsCount`)
     - დადებული ყადაღების რაოდენობა (`sequestrationCount`)
     - სასამართლოში მიმდინარე საქმეები (`inCourtCount`)
     - აღსრულებაში გადაცემული საქმეები (`inEnforcementCount`)
     - მოგებული საქმეები და მოგებული თანხა (`wonCount`, `wonAmountGel`)

4. **`GET /api/v1/analyst/bi/visitors-performance`**
   - პარამეტრები: `dateFrom`, `dateTo` (მაგ: 12 მაისი – 17 მაისი), `officerId`, `district`.
   - აბრუნებს ვიზიტორების მიერ განხორციელებულ ვიზიტებს დღეების მიხედვით, სტატუსებს (შესრულებული, გადადებული, ვერ მოიძებნა) და GPS ვალიდაციის პროცენტს.

5. **`GET /api/v1/analyst/bi/call-center-performance`**
   - პარამეტრები: `dateFrom`, `dateTo`, `hourFrom` (მაგ: `8`), `hourTo` (მაგ: `18`), `operatorId` (მაგ: თეონა), `teamLeadId`, `minCalls`.
   - აბრუნებს:
     - ოპერატორების მიერ 08:00–18:00 შუალედში განხორციელებული ზარების რაოდენობას საათობრივი ჩაშლით (`08:00`, `09:00` ... `18:00`).
     - შედეგების განაწილებას (გადახდის დაპირება PTP, უარი, უპასუხო).
     - ოპერატორების რეიტინგს (Leaderboard).

6. **`GET /api/v1/analyst/bi/statute-limitations`**
   - პარამეტრები: `monthsLookback` (მაგ: `4` თვე), `monthsLookahead` (მაგ: `4` თვე).
   - აბრუნებს:
     - ბოლო $N$ თვეში დაფიქსირებულ ახალ ვადაგადაცილებებს.
     - **დაკარგული მოთხოვნის უფლება (Expired > 3 Years)**: საქმეები, რომლებსაც ბოლო 4 თვეში შეუსრულდათ 3 წელი ვალის წარმოქმნიდან სასამართლო სარჩელის გარეშე.

## 6. შესრულების ეტაპები (Step-by-Step Implementation Roadmap)

1. **ეტაპი 1: მონაცემთა ბაზის განახლება და სატესტო/რეალისტური მონაცემებით შევსება (Seeding)**
   - `prisma/schema.prisma`-ს განახლება ახალი ველებით (`debtOriginationDate`, `founder*`, `branch`, `productType`, `sourceFile`, `callHour`, `durationSeconds`, `LegalCase` თარიღები და `outcome`).
   - ბაზის სინქრონიზაცია და მდიდარი ანალიტიკური მონაცემების გენერაცია (წინა წლისა და მიმდინარე წლის გრაფიკები, იურისტების 6 თვის სარჩელები/ყადაღები, თეონას და სხვა ოპერატორების 08:00–18:00 ზარები, ვიზიტორების კვირის ვიზიტები, 3-წლიან ხანდაზმულობასთან მიახლოებული და გადაცილებული საქმეები).

2. **ეტაპი 2: Backend BI სერვისისა და API ენდპოინტების შექმნა**
   - `AnalystService`-ში 5 სპეციალიზებული ანალიტიკური მეთოდისა და უნივერსალური მულტი-ფილტრის იმპლემენტაცია.
   - `AnalystController`-ში შესაბამისი REST ენდპოინტების დამატება.

3. **ეტაპი 3: Frontend სერვისისა და `/analyst/analytics` ქვეგვერდის აწყობა**
   - `analystBackendService.ts`-ში ახალი BI მეთოდების დამატება.
   - `/analyst/analytics/page.tsx`-ის შექმნა:
     - მარცხენა და მარჯვენა სვეტის სრული ფილტრაციის სისტემით;
     - 5 ინტერაქტიული ანალიტიკური ჩანართით (გრაფიკების YoY შედარება, იურისტების 6-თვიანი შედეგები, ვიზიტორების კვირის ანალიტიკა, ოპერატორების 08:00-18:00 ზარები, 3-წლიანი ხანდაზმულობის რადარი);
     - ინტერაქტიული Chart-ებითა და დეტალური ცხრილებით.
   - `/analyst/page.tsx`-დან ახალ ქვეგვერდზე გადასასვლელი ბმულების დამატება.

4. **ეტაპი 4: ტესტირება, ბილდის ვერიფიკაცია და დეპლოიმენტი**
   - ყველა ფილტრისა და სცენარის ტესტირება რეალურ მონაცემებზე.
   - Backend და Frontend ბილდის შემოწმება (`npm run build`) და სინქრონიზაცია.
